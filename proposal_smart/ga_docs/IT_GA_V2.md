# GA 스마트 제안서 새 양식(v2) 생성 프로그램 — IT 인계 안내

세일즈혁신TF · 2026-11-20(GA 최종 시안 반영) · 계산 버전은 `api.py` 의 `VERSION`(이 묶음을 만든 판은 맨 아래 `VERSION.txt`)

가입설계서 PDF(설계 시스템에서 「PDF 저장」으로 받은 원본) 한 건을 올리면 그 자리에서 읽고 계산해 **GA 스마트 제안서 새 양식 PDF(13~17쪽)** 를 돌려주는 프로그램입니다.
설계서 PDF 대신 **담보 목록(단위상품코드 · 담보코드 · 상품담보명 · 가입금액)을 JSON 으로 넘겨도** 같은 PDF 가 나옵니다(5장 「담보코드 입력」).
2026-11-11 회의에서 정한 「영업용 풀버전」 양식을 2026-11-18 회의에서 간결하게 줄였고, 지면 모양은 GA 가 보낸 **최종 시안(「스마트제안서 V5」 · 2026-11-20 받음)** 그대로입니다.
웹 서버(HTTP API + 업로드 화면)와 명령줄 두 가지로 돌릴 수 있습니다.
LLM · 외부 API 호출이 없고, 실행 중에 바깥 인터넷을 쓰지 않습니다.

## 1. 처리 흐름

```
PDF 업로드
 → ① 설계서 읽기      ga_proposal.load · pipeline / pdfplumber · PyMuPDF
                       피보험자 · 상품명 · 보험료 · 가입담보표(담보명 · 가입금액)
 → ② 담보 인식        matcher.py
                       특약 마스터 db.json(영업지원도구 감수본) + db_terms_extra.json(약관 PDF 파싱)
 → ③ 지급 계산        scen_engine.py + rules.json(지급 규칙) + ga_spec.py(칸 정의 · 사례)
                       칸마다 「어느 특약에서 얼마」 지급 줄을 만든다
 → ④ 지면 그리기      ga_v2.py
                       HTML → Chromium(playwright) PDF + GA 최종 시안 틀(ga_assets/v2/tpl.pdf) 위에 값 합성
 → PDF + 계산 로그(빈칸 · 0원이 된 이유)
```

### 쪽 구성

2026-11-18 회의에서 「치료 여정」 · 「보장 점검」 쪽과 체증형 시나리오 · 간병 보상 예시를 덜어 냈습니다(간결하게).

1. 표지 · 보장요약
2. 암 보장 ① ② · 뇌혈관 · 심장
3. 주요수술 ① ② — 수술 12개(쪽마다 6개). 수술명 옆에 「모든 병원 / 상급종합」 금액, 아래에 **늘 같은 다섯 줄**
   - 질병 수술 : 질병수술비 군 · 1-5종 수술비 · 1-7종 수술비 · 130대(131대) 질병수술비 · 그 외 수술비
   - 골절 : 상해수술비 군 · 1-5종 수술비 · 1-7종 수술비 · 골절수술비 및 그 외 수술비 · 골절 진단비
   - 줄마다 금액(가입) · 「미가입」(이 상품에 있고 이 수술에 지급되는데 설계에 없음) · 「해당 없음」(이 수술에는 지급되지 않음) 중 하나
   - 줄 옆 꼬리표 : 「체증형 · 최대 2배 체증」 · 「합산」(특약 여럿을 더한 줄 — 특약별 금액은 세부내역) · 「태아고급형」
   - 통합치료비의 수술(1-5종) 항목 · 신수술비 · 생활지원비는 「그 외 수술비」 줄에 더합니다(GA 최종 시안의 골절 카드 계산과 같음)
4. 간병인 쪽 — 아래 규칙대로 고른다(표 : 1~180일 / 181일 이상)
   - 간병인지원 담보 → 「간병인 지원」 쪽
   - 간병인사용 담보 → 「간병인 사용」 쪽
   - 둘 다 있으면 두 쪽
   - 둘 다 없으면 지원 표 + 사용 표를 함께 보여 주는 쪽
5. 보장금액 세부내역 — 담보 수에 따라 3~7쪽
   - 한 구분의 특약 줄이 한 쪽보다 길면 줄 단위로 나눠 다음 쪽에 잇습니다. 이어지는 조각은 구분 이름 아래 「(이어서)」, 보장금액은 회색 + 「앞 쪽과 같은 금액」(앞 조각에는 「다음 쪽에 이어짐」)
6. 안내사항

체증형 수술비는 지면에 1회차(가입금액 기준) 금액만 적고, 쪽 아래 주석(「※ 체증형 수술비 가입 시, 상기 예시 금액보다 더 큰 금액이 지급될 수 있습니다」)으로 알립니다.

### 금액 원칙

다음 세 가지는 바꾸지 말아 주세요(저장소 `CLAUDE.md`).

- **질병코드 · 금액을 추정하지 않습니다.** 약관 별표 · 지급금액표에 없으면 계산에서 빼고 로그에 남깁니다. 틀린 금액 대신 빈칸이 나옵니다.
- 지면 금액은 계산 엔진 칸 값 그대로입니다.
- 아래 두 경우에는 PDF를 만들지 않고 오류로 멈춥니다.
  - 수술 카드 합계 ≠ 보장요약 칸
  - 세부내역 구분 합계 ≠ 특약별 합

## 3. 설치

### 준비물

- **Python 3.10 ~ 3.13**(3.11 권장)
- 패키지 : `pip install -r requirements.txt`
  - pdfplumber · PyMuPDF · pypdf · reportlab · playwright · pillow
  - pypdf 는 7 미만(6.x)을 씁니다 — 7.x 는 원본 설계서에 지면을 끼우는 단계(`build_pdf.py`)에서 오류가 납니다
- PDF 를 그리는 Chromium : `python -m playwright install chromium`
  - 폐쇄망이면 이 단계 대신 PC 에 깔린 **Edge · Chrome** 을 씁니다.
  - 환경변수 `GA_CHROMIUM=<msedge.exe 경로>` 를 주면 세 양식(새 양식 · 기존 GA 6쪽 · 9쪽) 모두 그 브라우저를 씁니다. `start_offline.bat` · `make_ga_offline.bat` 이 경로를 넣어 줍니다.
  - `GA_CHROMIUM` 없이도 **새 양식**은 기본 설치 경로의 Edge · Chrome 을 찾아 씁니다. 기존 GA 6쪽 · 9쪽은 `GA_CHROMIUM` 이 있어야 합니다.
- 인터넷이 없는 PC 에서 패키지를 설치하는 방법(`start_offline.bat` 이 이 목록 그대로 설치합니다)
  1. 인터넷 되는 PC 에서 아래 명령으로 `wheels` 폴더를 만듭니다.
     ```
     python -m pip download pdfplumber "pymupdf<1.26" "pypdf<7" reportlab playwright pillow openpyxl -d wheels --platform win_amd64 --only-binary=:all: --python-version 3.11
     ```
  2. `wheels` 폴더를 묶음 폴더 안에 옮겨 두고 `start_offline.bat` 을 실행합니다. 직접 설치할 때는 아래 명령입니다.
     ```
     python -m pip install --no-index --find-links wheels pdfplumber "pymupdf<1.26" "pypdf<7" reportlab playwright pillow openpyxl
     ```

## 4. 실행

### 웹 서버(업로드 화면 + API)

```
python api.py                    # http://127.0.0.1:8080
python api.py 0.0.0.0 8080       # 다른 PC 에서 접속하게
```

1. 브라우저에서 `http://<서버>:8080/` 을 엽니다.
2. PDF 를 끌어다 놓습니다.
3. **「GA 새 양식 생성」** 을 누릅니다.
4. 20초 안팎이면 다음이 보입니다.
   - 미리보기 · 쪽수 · 간병인 쪽 · 인식 담보 · 계산 로그
   - PDF 내려받기

윈도우는 `start_windows.bat` 을 두 번 누르면 됩니다(맥 · 리눅스 `start.sh`).

### 명령줄

```
python ga_v2.py 설계서.pdf 결과.pdf     # 한 건
python ga_v2.py 폴더                     # 폴더 안 PDF 전부 → ga_output\<이름>_GA2.pdf + _log.txt
GA_MASK=1 python ga_v2.py 설계서.pdf     # 피보험자 · 설계번호 · 소속 · 컨설턴트 · 전화를 가린 견본
```

## 5. API — 새 양식

요청은 두 방식 모두 받습니다.

- `Content-Type: application/pdf` 로 PDF 바이트를 본문에 그대로
- `multipart/form-data` 의 `file` 필드

업로드 상한은 60MB 입니다.

| 주소 | 응답 |
|---|---|
| `POST /v1/ga2/pdf` | 새 양식 PDF(`application/pdf`, `ga2_proposal.pdf`) |
| `POST /v1/ga2/all` | JSON(아래) |
| `GET /health` | `{"ok":true,"version":…,"formats":{…}}` |

### 담보코드 입력(JSON) — 설계서 PDF 없이

전산이 가지고 있는 담보 목록(단위상품코드 · 담보코드 · 상품담보명 · 가입금액)을 그대로 넘깁니다. 설계서 PDF 를 읽는 단계만 바뀌고, 계산 · 지면은 PDF 로 넣었을 때와 같은 길입니다.

| 주소 | 응답 |
|---|---|
| `POST /v1/ga2/json/pdf` | 새 양식 PDF(`application/pdf`) |
| `POST /v1/ga2/json/all` | JSON — `/v1/ga2/all` 과 같은 필드 + `input:"json"` · `line`(판정한 상품 라인) · `riders[].how` |
| `POST /v1/ga2/json/check` | PDF 를 만들지 않고 입력 점검 + 담보 인식 결과만(빠름) — `rider_count` · `matched` · `recog` · `riders` · `issues` |

요청 본문(`Content-Type: application/json` · UTF-8 · 상한 2MB)

```json
{
  "schema": 1,
  "design_no": "가계약번호",
  "product": "(무) 메리츠 통합간편건강보험(세만기형)2610(통합간편심사형) (해약환급금미지급형)",
  "premium": 123450,
  "insured": {"name": "홍길동", "sex": "M", "age": 45},
  "agent": {"org": "○○본부", "code": "00000", "name": "김메리", "mobile": "010-0000-0000", "tel": "02-0000-0000"},
  "riders": [
    {"no": 1, "unit_code": "X0000", "code": "000001", "name": "암진단비(유사암제외)(통합간편가입)", "amount": 30000000},
    {"no": 7, "unit_code": "X0000", "code": "000007", "name": "수술비(1-7종, 연간3회한)[질병1종](통합간편가입)", "amount": 200000},
    {"no": 13, "unit_code": "X0000", "code": "000013", "name": "갱신형 간병인지원 질병입원일당(Ⅰ)(1일이상 180일한도)(통합간편가입)", "amount": 0, "unused_daily": 20000}
  ]
}
```

| 항목 | 필수 | 뜻 |
|---|---|---|
| `product` | 필수 | 상품명 원문. 특약 마스터의 상품 라인을 정하고 표지에 적습니다 |
| `riders[].name` | 필수 | **정보계 상품담보명 원문 그대로.** 고지 구분자 `(○○가입)` · `[기본계약]` · `(N년갱신)` · `[특별조건부]` 가 붙어 있어도 됩니다. 엔진이 이름에서 조건(원인 · 병원 종별 · 종 · 일수 · 연간1회한)을 읽으므로 줄이거나 바꾸지 않습니다 |
| `riders[].amount` | 필수 | 가입금액(원). 금액 없는 부모 줄(「세부보장 참조」)은 넘기지 않아도 되고, 넘겨도 계산하지 않습니다 |
| `riders[].unit_code` · `code` | 권장 | 단위상품코드 · 담보코드. 이름으로 특약을 못 찾았을 때 담보 식별표로 찾는 데 쓰고, 응답 · 로그에 그대로 실립니다 |
| `riders[].no` | 선택 | 담보 번호(없으면 순서) |
| `riders[].unused_daily` | 선택 | 간병인지원 입원일당(현물)의 「간병인 미사용 시 입원일당」(원) |
| `design_no` · `premium` · `insured` · `agent` | 선택 | 표지 · 머리줄 · 바닥 글. 없으면 「-」 로 두고 로그에 남깁니다. `sex` 는 `M`/`F`, `age` 는 보험나이 |

- 1-7종 수술비 세부보장은 종마다 한 줄씩 넘깁니다. `수술비(1-7종, 연간3회한)[질병3종]` · `수술비[질병3종]` 두 꼴 모두 받습니다.
- 담보 찾기 : ① 담보명으로 특약 마스터를 찾고(설계서 PDF 와 같은 길 · `how:"name"`) ② 못 찾으면 담보 식별표(`code_map.json`)로 찾고(`how:"code"`) ③ 그래도 없으면 그 담보만 계산에서 빼고 로그에 남깁니다(`how:null`).
- 담보 식별표 `code_map.json` 은 정보계 코드가 든 사내 자료라 묶음에 없습니다. 환경변수 `GA_CODE_MAP=<경로>` 로 주거나 프로그램 폴더에 둡니다. **없어도 됩니다** — 그때는 이름으로만 찾습니다.
- 오류 : 입력이 사양과 다르면 400 + 무엇이 다른지, 담보를 하나도 못 찾으면 422, 나머지는 PDF 입력과 같습니다.

```

python ga_v2.py --json ga_docs/code_input_example.json 결과.pdf        # 서버 없이
python check_code_input.py                                             # 입구 자체 시험(전부 통과여야 함)
```

### 오류 응답

모든 오류는 JSON `{"ok":false,"error":"…"}` 로 옵니다.

| 코드 | 뜻 |
|---|---|
| 400 | PDF 가 아님(사내 보안 DRM 으로 잠긴 파일이면 그렇게 알려 줌) · 본문 없음 · 60MB 넘음 |
| 422 | 설계서를 읽지 못해 만들지 않음(v8.98) — 글자가 없는 그림 PDF(스캔 · 캡처) · 깨진 · 암호 PDF · 가입설계서가 아닌 문서 · 담보를 하나도 못 찾음. `error` 에 이유와 할 일이 쉬운 말로 들어 있으니 화면에 그대로 보여 주세요 |
| 422 | 만들지 않는 상품(`rules.json > exclude_products` 에 적은 상품). `error` 에 이유가 들어 있음. 설계서 PDF · 담보코드 입력 모두 같음. **v9.10 부터 목록이 비어 있어 지금은 나오지 않습니다** — 프리미엄 건강보험 · 프리미엄 간편보험도 만듭니다. 「(체증형,10년후2배지급)」 담보는 가입 직후(10년 전) 금액 = 일반형과 같은 금액으로 적습니다 |
| 503 | 대기가 180초를 넘음, 또는 새 양식 작업이 멈춰 재시작이 필요한 상태 |
| 504 | 새 양식 1건이 600초(환경변수 `GA2_TIMEOUT` 로 바꿈)를 넘김(지면을 그리는 크로뮴이 멈춘 것으로 봄). 그 뒤로 `/health` 가 503 이 되니 서버를 다시 켜 주세요 |
| 500 | 생성 중 오류. 수술 카드 · 세부내역 합계 점검에 걸린 경우를 포함하며, 메시지에 이유가 들어 있음 |

## 6. 운영할 때 알아 둘 것

- **동시 처리**
  - 서버 프로세스 하나에서 생성은 **한 번에 1건**씩입니다(새 양식 · 기존 GA 6쪽 · 9쪽 모두 같은 줄). 동시에 들어오면 차례로 처리하고, 2건까지 받아 두며, 180초 넘게 기다리면 503 입니다.
  - 설계서 상태와 계산 로그를 모듈 안에 두기 때문이고, 새 양식은 지면을 그리는 Chromium 을 하나 띄워 두고 같은 작업 스레드에서만 씁니다(playwright 규칙).
  - 처리량을 늘리려면 **프로세스를 여러 개(포트마다 하나) 띄우고 앞에 부하분산**을 두세요. 프로세스마다 메모리 약 1GB 를 잡아 주세요.
- **상태 확인 · 재시작**
  - `GET /health` 는 정상이면 200, 새 양식 작업이 600초를 넘겨 멈춘 뒤에는 503(`ok:false`)입니다. 부하분산 · 서비스 관리자가 이것을 보고 프로세스를 다시 켜게 해 주세요.
  - Chromium 이 처리 중에 죽으면 새로 띄워 그 건을 한 번 더 만듭니다.
- **개인정보**
  - 설계서에는 고객 · 설계사 정보가 있습니다.
  - 업로드 파일은 건마다 임시 폴더(운영체제 임시 폴더의 `sp_in_*`)에 두고 응답 뒤 지웁니다. 9쪽 지면 작업 폴더도 그 안에 만듭니다.
  - 새 양식 중간 파일(HTML · PDF 조각)은 `out/v2tmp/job_*` 에 만들고 끝나면 지웁니다. `GA_V2_KEEP=1` 이면 남겨 두며, 지면 점검용입니다.
  - 처리 중에 서버가 꺼져 남은 것은 서버를 켤 때와 요청이 올 때 「만든 지 1시간 넘은 것」 을 지웁니다.
  - 서버는 결과를 저장하지 않습니다.
- **인증 · CORS**
  - `api.py` 에는 인증이 없고, CORS 는 모든 출처(`*`)를 허용합니다.
  - 사내망 안에서만 열고, 필요한 인증 · 허용 출처는 앞단(게이트웨이 · 리버스 프록시)이나 `api.py` 의 `_cors` 에서 맞춰 주세요.
- **로그** : 접속 로그는 표준 오류 출력에 한 줄씩 나옵니다. 계산 로그는 응답의 `log` 에 들어 있습니다.
- **미리보기** : 업로드 화면의 미리보기는 브라우저의 PDF 뷰어로 보여 줍니다(Edge · Chrome 기본 기능).
- **넣는 파일** : 설계 시스템에서 「PDF 저장(다운로드)」으로 받은 **가입설계서 원본 PDF** 입니다(첫머리에 「가입담보리스트」 표가 있는 것).
  - 스캔본 · 화면 캡처 · 「그림으로 인쇄」 한 PDF, 사내 보안(DRM)으로 잠긴 파일, 청약서 · 상품설명서만 따로 받은 파일, 이미 만든 제안서는 담보를 읽지 못합니다.
  - v8.97 까지는 이런 파일도 멈추지 않고 금액이 모두 「0만원」 · 이름이 「-」 인 빈 제안서를 만들었습니다. **v8.98 부터는 만들지 않고 이유를 알려 줍니다**(API 422 · 명령줄은 결과 폴더에 `…_FAILED.txt` — 같은 설계서가 다음에 만들어지면 지워짐).
  - 설계서에서 담보를 한 건이라도 계산할 수 있으면 지금처럼 만들고, 못 찾은 담보만 계산 로그에 「계산 제외」 로 남깁니다.

## 7. 약관 · 데이터가 바뀔 때

- 특약 마스터 · 지급 규칙은 저장소(`main`)에서 관리합니다.
- 약관 판이 바뀌면 TF 가 저장소에서 `python3 scripts/sync_all.py` 로 마스터를 갱신하고 점검을 통과시킵니다.
- 그다음 **이 묶음을 다시 만들어 드립니다.** 저장소 루트에서 `python3 scripts/build_ga_v2_package.py` 를 실행합니다.
- 변경 내용은 `README.md` 맨 위 변경 기록에 버전별로 있습니다.
- 신담보가 나왔을 때의 전체 순서(약관 → 마스터 → 규칙 → 점검 → 담보코드 매핑 → 설계도 → 묶음)는 `ga_docs/NEW_RIDER_UPDATE.md` 에 있습니다. 반영 전에 처음 보는 담보가 든 설계서가 와도 그 담보만 계산에서 빠지고 로그에 남습니다(기존 칸 값은 그대로).
- 디자인만 바뀔 때는 `ga_docs/DESIGN_SWAP.md` 순서대로 하고 `verify_v2.py` 로 값이 그대로인지 확인합니다.

### 받은 뒤 점검

- `python harness.py` — H1~H5 가 「전부 통과」 여야 합니다.
- `python check_code_input.py` — 담보코드 입력 자체 시험. 「전부 통과」 여야 합니다.
- `python check_detail_split.py` — 세부내역 쪽 나눔 자체 시험(약 15초). 「전부 통과」 여야 합니다.
- `python verify_v2.py <설계서 PDF 또는 폴더> [결과 폴더]` — 설계서마다 PDF 를 만들고 그 PDF 의 글자를 다시 읽어 계산 값과 대조합니다. 「결과 : 전부 통과」 여야 합니다(하나라도 다르면 무엇이 어디서 다른지 적고 종료코드 1).
- 업로드 화면에서 설계서 한 건을 만들어 보세요.
  - 계산 로그 4번째 줄(「담보 N건 · N쪽 · 간병인 쪽 : …」)의 쪽수 · 간병인 쪽이 화면과 같은지 봅니다.
  - `[지면 경고] 없음` 인지 봅니다.
