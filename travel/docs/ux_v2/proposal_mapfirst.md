# 일본 직항 여행 플래너 v2 : 지도 중심 설계안

> 관점 : **지역마다 색이 다른 큰 지도가 주인공**이다. 글은 지도 아래에서 올라오는 시트(바텀 시트)에만 조금씩 둔다.
> 기준 화면 : 아이폰 13(폭 390px, 사파리에서 실제로 보이는 높이 약 750px. 주소창이 펼쳐져 있으면 약 664px). 320px(아이폰 SE 1세대)·430px(프로 맥스)에서도 깨지지 않게 한다.
> 소유자 요청 세 가지와의 대응 : ① 박 수부터 고르고 넘어가기 → 첫 방문 질문 시트(S0) ② 큰 지도·지역 색·터치하면 커지기 → S1·S2 ③ 실물 사진이나 분위기 그림 → 8장(사진 자리와 그림 대신 쓰기)

## 0. 한 장 요약

```
첫 방문 : [지도 위 질문 시트] 며칠? (탭 1) ─▶ [일본 전체 색 지도] 지역 누르기 (탭 2)
          ─▶ [지역 확대 + 도시 카드 줄] 도시 누르기 (탭 3) ─▶ [도시 미리보기 시트] "2박 3일 일정 보기" (탭 4)
          ─▶ [여행 화면 = 전체 화면 지도 + 아래 시트(일정·맛집·숙소·준비 탭)]
다시 올 때 : 고른 박 수·공항이 저장돼 있어 탭 3번. 인기 도시 카드나 검색으로 가면 2~3번.
```

- 첫 화면에서 일정표까지 **탭 4번**(지금은 공항·박 수·지도·카드를 지나 목적지 화면에서 박 수를 또 고르고 2천 px 넘게 내려야 일정이 나온다).
- 화면마다 **처음 보이는 글자 수 상한**을 정해 둔다(10장). 설명·영업시간·팁은 누르면 나오는 곳으로 옮긴다.
- 지도는 두 가지다. 홈의 **색 지도(SVG, 인터넷 없이 동작)** 와 여행 화면의 **상세 지도(Leaflet 지도 그림)**. 둘 다 "지도가 화면 전체, 글은 아래 시트" 라는 같은 틀을 쓴다.

### 1-5. 결정이 겹치는 곳
1. 박 수 : 홈 칩 → 목적지 화면 박 수 버튼 → 대체 플랜 칩(박 수별)
2. 지역 : 지역 칩 ↔ 지도 확대 ↔ 아래 목록 지역 머리글
3. 도시 소개 : 카드 ↔ 지도 핀 소개 상자 ↔ 목적지 "한눈에 보기" (같은 먹/볼/할이 세 곳에)

## 2. 설계 원칙

1. **화면 = 지도 + 시트.** 화면 전체에 지도를 깔고, 글은 아래에서 올라오는 시트에만 둔다. 시트는 손가락으로 올리고 내린다(낮게·중간·높게 세 단계).
2. **한 화면에 결정은 하나.** 박 수 → 지역 → 도시 → 일정. 같은 것을 두 번 묻지 않는다. 박 수는 한 값(`st.nights`)만 있고, 어디서 바꾸든 모든 화면에 반영된다.
3. **처음에는 이름과 그림만, 설명은 누르면.** 장소 한 줄 = 시각 + 그림 + 이름 + 짧은 한 줄.
4. **누르는 것은 모두 44px 이상.** 지도 위 작은 것(지역·도시)은 보이는 크기보다 눌리는 범위를 더 크게 잡는다.
5. **사진이 없으면 그림, 그림도 없으면 색.** 이미지 자리는 처음부터 만들어 두고 사진이 들어오면 그 자리만 바뀐다.
6. 지금 진행 중인 작업과 맞춘다 : 틀에 이미 들어온 `openSheet/closeSheet`(모달 시트, 뒤로 가기로 닫힘), `.rmap`(지역 색 지도 CSS), `data/regions_geo.json`(지역별 `d`·`label`·`bbox`, 지도 좌표 331×320), `REGION_KEYS`(hokkaido…okinawa), `photos.json`(조립 때 `data:` 로 넣음, `{src, credit, license, source, alt}`), 식당 `dish` 값(`tools/dish_category.py`, 23종), `art_regions.json`(지역 장면 ≤8KB)·`art_dishes.json`(음식 그림 ≤4KB).

### S0. 첫 질문 시트 (지도 위에 뜨는 시트, 첫 방문만)

뒤에 S1 지도가 흐리게(색만, 이름표 없이) 깔려 있다. 시트는 화면 아래 약 560px.

```
┌──────────────────────────────────────┐
│ (흐린 일본 색 지도)                      │
├─────────────── ▬▬ ───────────────────┤  ← 손잡이 20
│ 일본, 며칠 다녀오세요?                    │  24px 굵게 · 36
│ 고르면 그 일정에 맞춰 보여 드려요           │  15px 회색 · 24
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ 2박 3일            핵심만 빠르게   │ │  카드 358×64 (19px 굵게 / 15px 회색)
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ 3박 4일            근교까지 하루 더 │ │  64
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ 4박 5일            여유 있게 천천히 │ │  64
│ └──────────────────────────────────┘ │
│            아직 몰라요                  │  글자 버튼 15px · 44
│ ──────────────────────────────────── │
│ 출발 공항   인천 · 직항 33곳      바꾸기 ›│  44 (누르면 아래로 펼침)
```

- 박 수 카드를 누르면 **바로** 시트가 내려가고 S1 이 살아난다(지역 색이 0.3초 동안 차오름). 별도 "다음" 버튼 없음.
- 박 수 목록은 자료에 있는 박 수만 만든다(지금 2·3·4. 기존 `nightsAvail` 계산 그대로).
- "바꾸기" 를 누르면 그 자리에 공항 버튼 2열 격자가 펼쳐진다(각 171×48): `인천 · 33곳` `김해 · 22곳` `청주 · 18곳` `대구 · 13곳` `제주 · 11곳` `김포 · 8곳`. 숫자는 그 공항에서 직항이 있는 도시 수(정기·계절·전세, 확인 필요·운휴 제외)를 조립 때가 아니라 화면에서 센다. 직항 도시가 0곳인 공항(지금 무안)은 숨긴다.
- 기본 공항은 지난번 값, 처음이면 인천.
- 이미 저장된 박 수가 있으면 S0 을 띄우지 않는다(`jptrip:seen_start`).

### 4-1. 주소 문법 (영어·숫자만 → 6개 언어 파일 사이에서 그대로 통한다)
```

```

### 4-2. 기록을 쌓을지(push) 바꿔 끼울지(replace)
| 무엇이 바뀌나 | 방식 | 뒤로 가기 하면 |
|---|---|---|
| 일본 → 지역, 지역 → 도시 미리보기, 미리보기 → 여행 화면 | 쌓기 | 한 단계 위로 |
| 지역 → 이웃 지역(흐린 지역 누름), 미리보기 → "헷갈린다면" 도시 | 바꿔 끼우기 | 같은 단계의 이전이 아니라 한 단계 위로 |
| 탭 · 일차 · 대체 동선 · 박 수 | 바꿔 끼우기 | 여행 화면에서 바로 미리보기로 |
| 덮개(~) 열기 | 쌓기 | 덮개만 닫힘 |
| 덮개를 X·바깥 누르기·끌어내리기로 닫기 | `history.back()` | (기존 `SH.ignorePop` 방식) |
| 검색 결과 누름 | 검색 덮개를 바꿔 끼우며 이동 | 지도로 |

### 4-3. 공유 링크로 바로 들어왔을 때(가짜 뒤로 가기 길 만들기)
`#trip/kyoto/2` 로 열리면 처음에 `replaceState('#map/kansai/kyoto')` 다음 `pushState('#trip/kyoto/2')` 를 한다. 그래서 브라우저 뒤로 가기·아이폰 왼쪽 끝 스와이프를 해도 앱 밖으로 나가지 않고 교토 미리보기로 간다. `#map/kansai/kyoto` 로 열리면 `#map` 위에 `#map/kansai` 를 하나 깔아 둔다. 기록에는 `{depth}` 를 넣어, 화면 안 "‹" 버튼이 `depth > 0` 이면 `history.back()`, 아니면 부모 주소로 바꿔 끼운다(지금의 `st.pushed` 셈보다 새로고침에 강하다).

### 4-4. 전환 효과
| 이동 | 효과 | 시간 |
|---|---|---|
| 일본 → 지역 | 지도 보는 범위(viewBox)를 부드럽게 좁힘(기존 `animateMap`, 끝이 느려지는 곡선) + 다른 지역 25%로 흐려짐. 도시 표시는 확대 중엔 숨겼다가 끝나면 20ms 간격으로 하나씩 나타남 | 420ms + 160ms |
| 지역 → 미리보기 | 고른 도시 표시 1.25배, 지도가 그 도시를 시트 위 가운데로 옮김, 시트가 중간 단계로 올라옴 | 280ms |
| 미리보기 → 여행 화면 | 시트가 화면 끝까지 커지며 내용이 바뀌고, 그 아래로 상세 지도가 서서히 나타남(색 지도 → 상세 지도 흐리게 바뀜) | 260ms |
| 탭·일차 바꾸기 | 목록 흐리게 바꿈 + 지도는 새 범위로 맞춤(fitBounds 애니메이션) | 150ms / 300ms |
| 덮개 열기·닫기 | 아래에서 올라옴 / 내려감 | 260ms |
| **뒤로 가기로 생긴 변화** | 아이폰 스와이프는 사파리가 이미 화면을 밀어 주므로 **슬라이드를 또 하지 않고** 150ms 흐리게 바꿈만. 지도 축소는 250ms | 150~250ms |
| 움직임 줄이기 설정 | 전부 즉시 | 0 |

## 5. 큰 색 지도 상호작용

### 5-1. 일본 전체(S1)
- 지도 무대는 화면 전체(위쪽 줄은 지도 위에 떠 있음). 그리는 범위는 한국 대부분을 잘라 낸 **x 10~328, y 9~316(지도 단위)** — 일본 본토와 오키나와 상자가 폭 358px 에 꽉 차게(1단위 ≈ 1.13px). 남는 아래 공간은 시트가 쓴다.
- 이 배율에서 지역 크기 : 홋카이도 114×93px, 주부 79×90, 규슈 62×101, 도호쿠 52×107, 주고쿠 65×58, 시코쿠 49×42, 간사이 47×53, 간토 44×93, 오키나와 상자 106×77. 모두 손가락(약 44px)보다 크지만 시코쿠 세로가 아슬아슬하다.
- 누르는 방법은 세 가지가 모두 같다 : ① 지역 색 칠한 곳 ② 지역 이름표 알약 ③ 이름표 둘레 반지름 24px 투명 원(작은 지역을 위해). 바다를 누르면 아무 일도 없다.
- 두 번 누르기 = 그 지역 확대. 두 손가락 벌리기 = 손가락 사이 가운데 지역으로 확대(연속 확대가 아니라 **단계 바꾸기** 신호로만 씀). 오므리기 = 일본 전체로.
- 지도 위에서는 페이지가 움직이지 않게 `touch-action:none`(아이폰이 화면 전체를 확대해 버리는 것을 막음).

### 5-2. 지역 확대(S2) 확대 규칙
보이는 지도 범위 = 화면 폭 390 × (화면 높이 − 위쪽 줄 56 − 시트 226) ≈ 390×468px.
1. 기본 : 그 지역 경계 상자(`regions_geo.bbox`)에 여백 8%를 두고 꽉 차게.
2. 도시 표시가 서로 64px 이상 떨어지도록, 가장 가까운 두 도시 거리로 필요한 배율을 구한다.
3. 2번 배율이 1번보다 크면 2번을 쓰되, 그 지역 도시들을 모두 감싸는 상자 + 사방 56px 이 화면에 들어가는 만큼까지만 키운다.

자료로 계산한 결과(390×468 기준) :

| 지역 | 가장 가까운 두 도시 | 쓰는 배율 | 그때 거리 |
|---|---|---|---|
| 간사이 | 오사카–나라 3.7단위 | 17.3px/단위 (도시 4곳 둘레만 보임, 와카야마·미에 쪽은 잘림) | 64px |
| 규슈 | 후쿠오카–사가 7.5단위 | 약 7.6 (도시 상자에 막힘) | 약 57px |
| 간토 | 도쿄–하코네·가마쿠라 7.6단위 | 8.4 | 64px |
| 주부 | 가나자와–도야마 11.0단위 | 약 5.2 | 약 57px |
| 홋카이도·도호쿠·주고쿠·시코쿠 | 18~49단위 | 지역 꽉 차게(3.3~7.8) | 70px 이상 |
| 오키나와 | 본섬–이시가키 72단위 | **오키나와 상자(x 10~104, y 10~78)** 를 꽉 차게. `regions_geo` 의 오키나와 bbox 는 상자 밖 섬까지 잡혀 있어(15~147, −16~69) 쓰지 않는다 | 270px 이상 |

- 64px 미만(규슈·주부)에서는 이름표를 위·왼쪽·오른쪽으로 바꿔 놓고(기존 이름표 자리 고르기 함수 재사용, 상자만 크게), 그래도 겹치면 이름표를 숨기고 둥근 그림만 둔다(카드 줄에 이름이 있으므로).
- 확대된 상태에서 흐린 이웃 지역을 누르면 그 지역으로 바로 옮긴다(바꿔 끼우기). 한 손가락으로 끌어 옮기기는 하지 않는다(필요 없게 범위를 잡았다).
- 오키나와 상자 : 일본 전체에서 상자 어디를 눌러도 오키나와로 확대. 확대 뒤에는 상자 테두리를 지우고 두 섬을 크게.

### 5-3. 도시 표시
- 둥근 그림 44px(도시 그림 `g.icon`. 작은 원 안의 사진은 알아보기 어려워 **사진이 생겨도 여기는 그림 유지**) + 흰 테 3px + 그림자, 아래 이름표(15px 굵게, 흰 알약 높이 26).
- 고른 도시 : 56px, 장미색 테 3px, 살짝 튀어 오름.
- 계절편·전세편 : 오른쪽 위에 작은 표("계절" 햇빛색 / "전세" 자두색, 12px).
- 직항 없음 : 흑백(`filter:grayscale(1)`) + 70% 투명, 이름표 회색.
- 고른 박 수의 일정이 없음(나중 자료) : 이름표 옆 "3박까지" 작은 표.
- 가이드가 없는 공항(이바라키·도쿠시마 등)은 지도에서 뺀다. 그 정보는 그 근처 도시의 준비 탭 "다른 공항" 에 남긴다.

## 6. 여행 화면 : 지도와 시트의 관계

| 탭 | 시트에 보이는 것 | 지도에 보이는 것 |
|---|---|---|
| 일정 | 일차 알약 + 그날 장소 줄 | 그날 장소 번호(장소 장미·식사 햇빛·숙소 자두) + 점선 순서 |
| 맛집·명소 | 맛집 24 / 명소 27 목록 | 전부. 맛집은 음식 그림 표시 36px, 명소는 분류 아이콘 |
| 숙소·예산 | 예산 상자 + 숙소 카드 | 숙소마다 **값 알약**("18만~", 높이 32, 눌리는 범위 44) — 에어비앤비처럼 |
| 준비 | 직항편·공항 교통·준비물… | 도착 공항 → 중심 역 길(공항 교통 첫 줄) |

- 목록을 스크롤하면 맨 위에 걸린 줄의 표시가 지도에서 커진다(지도는 그 표시가 화면 밖일 때만 움직인다 — 멀미 방지).
- 지도 표시를 누르면 그 줄로 목록이 굴러가고 줄이 잠깐 빛난다. 시트가 낮은 단계였으면 중간으로 올라온다.
- 지도를 맞출 때는 시트가 가린 아래쪽을 빼고 맞춘다(Leaflet `fitBounds(…, {paddingBottomRight:[0, 시트 높이]})`).
- 상세 지도 그림을 못 받으면(인터넷 없음) 기존 번호 약도로 바꾸되, 약도 크기를 시트 위 보이는 부분에 맞춘다.

## 7. 일정 화면에서 글씨를 줄이는 방법

### 7-1. 처음부터 보이는 것 / 눌러야 보이는 것
| 처음부터 | 눌러야(어디서) |
|---|---|
| 일차 이름("1일 히가시야마"), 일차 제목 | 일차 설명(`note`) → "이 날 설명 ›" 누르면 그 자리에서 펼침 |
| 주의 사항이 있다는 표시("⚠ 휴무 주의") | 주의 내용(`notice.t`) → 칩 누르면 펼침 |
| 시각 · 그림 · 이름 · 짧은 한 줄 | 설명 · 영업시간 · 가는 법 · 팁 · 아이와 팁 · 지도 버튼 → 줄 누르면 상세(S5) |
| 이동 : 탈것 아이콘 + "JR 1시간 20분" | 이동 문장 전체(요금·노선) → 이동 줄 누르면 펼침 |
| 식사 : 고른 식당 이름 + "후보 2곳" | 후보 비교 → 식사 줄 누르면 후보 시트 |
| 필수 표시(작은 장미색 점 + "필수") | 입장료 → 상세 |
| 숙소 줄 "숙소 · 체크인" | 숙소 설명·값 → 상세 |
| 휴무가 있는 곳은 줄 끝 작은 달력 아이콘(16px, 읽어 주기 "화요일 휴무") | 휴무 요일 → 상세 |
| 플랜 요약(`summary`), 테마 | ⋯ 메뉴 "이 동선 설명" |

### 7-2. 장소 줄(64px) 모양
```
10:30  [그림40]  기요미즈데라·기요미즈 무대   ●필수   ›
                 히가시야마 · 1시간 30분
```
- 시각 열 48px(15px, 숫자 폭 고정) / 그림 40px(모서리 12) / 이름 16px 600 한 줄(넘치면 …) / 아래 13px 회색 한 줄 / 오른쪽 › .
- 한 줄 = 장소 하나. 하루 평균 13.2 항목 중 이동(약 5개)은 28px 이음 줄이라 하루가 약 700px(지금 3천 px 넘음).

### 7-3. 식당 후보 고르기 `~m5`
```
‹ 1일차        점심 · 후보 2곳
┌────────────────────────────────────┐
│[라멘 그림96]  혼케 다이이치아사히 ✓ 고른 집│ 카드 358×128
│             라멘 · 1인 1,500엔 안팎      │ 이름 17px 굵게 / 15px / 13px
│             특제 라멘(교토 간장 라멘)      │
│             06:00–다음 날 01:00 · 목 휴무 │
│             [자세히 ▾]                  │
└────────────────────────────────────┘
┌────────────────────────────────────┐
│[라멘 그림96]  교토 라멘코지     [이 집으로]│ 버튼 44
└────────────────────────────────────┘
```
- 세로로 쌓는다(후보가 2~4곳이라 가로 넘기기보다 한눈에 비교가 쉽다. 자료 집계 : 3곳 453번, 2곳 360번, 4곳 16번).
- 지도에는 후보 모두가 A·B·C 음식 표시로 뜨고, 고른 집이 그날 번호를 받는다. 고르면 점선 길이 바로 다시 그려진다.
- 고른 값은 지금처럼 기기에 저장(`jptrip:picks`, 키 모양 그대로).
- "자세히" 를 펼치면 설명·팁·예약 필요·구글 지도 버튼.

### 7-4. 일정 탭 맨 아래
- "다른 동선" 카드 : 같은 박 수의 대체 동선(예 : 아이와 플랜 3박4일, 온천 느긋 플랜 3박4일). 누르면 바꿔 끼우기.
- "비 오거나 지칠 때 · 8곳 ›" → 플랜 B 목록 `~b` (카드마다 때 표시 칩 + 한 줄 설명, 지도에 위치).
- "비슷한 다른 도시 ›" → 대체 여행지 카드(그림 64 · 이름 · 이유 두 줄 · ✈ 시간). 누르면 그 도시 미리보기(S3)로.

## 9. 사진이 없을 때 그림으로 대신하는 방법

### 9-1. 한 함수로 모든 이미지 자리를 그린다
`pic(종류, 키, 크기)` → 사진이 있으면 `<img>`, 없으면 아래 그림. 사진은 그림 위에 겹쳐 두고 다 읽히면 0.2초 동안 나타나게 한다(읽다 실패해도 그림이 남는다).

| 자리 | 사진이 있을 때(`photos.json`) | 사진이 없을 때 |
|---|---|---|
| 도시 미리보기 대표(S3) 358×160, 인기 도시·지역 카드·목록 줄 그림 | `cities[key][0]` (가운데 맞춰 자름) | **지역 장면 그림(3:2, 가운데 맞춰 자름)을 바탕** + 왼쪽 아래 도시 그림 88px(흰 테 4px, 모서리 20). 장면 그림도 없으면 도시 색 연한 배경 + 도시 그림 가운데 120px |
| 지도 도시 표시 44px | 쓰지 않음 | 도시 그림 |
| 지역 머리 그림(목록 S1-L) 358×88 | `regions[key][0]` | 지역 장면 그림 |
| 먹을 것 칸(S3) | `dishes[dish][0]` | 음식 그림(먹을 것 글을 `dish_of` 로 분류. 조립 때 `profile.known_for` 의 eat 에 `dish` 를 붙인다) |
| 볼 것·할 것 칸(S3) | 그 명소 사진(`spots[id]`. 조립 때 known_for 글과 명소 이름이 맞는 것) | 볼 것 = 도시 그림, 할 것 = 명소 분류 아이콘(기존 `I[cat]`) 큰 것 |
| 일정 장소 줄 40px · 장소 상세 358×200 | `spots[id][0]` | 분류 아이콘(신사·공원·시장…)을 분류 색 연한 바탕 위에. 상세는 아이콘 64px + 아래에 도시 그림 흐리게 |
| 식사 줄 40px · 후보 카드 96px · 맛집 줄 56px | `dishes[dish][0]` (가게 사진이 아니라 **음식 예시 사진**) | 음식 그림 23종(식당 `dish` 값) |
| 숙소 카드 | 넣지 않음(사용 허가가 분명한 숙소 사진을 구하기 어렵다) | 지역 장면 그림 + 등급 아이콘(온천=김, 비즈니스=건물) |

### 9-2. 사진이 들어오면 바뀌는 곳(정리)
도시 미리보기 대표 · 인기 도시 카드 · 지역 카드 · 목록 줄 그림 · 지역 머리 그림 · 먹/볼/할 칸 · 일정 장소 줄·장소 상세 · 식사·맛집 그림. **지도 위 도시 표시와 숙소는 그대로 그림.**

### 9-3. 사진 표기
- 사진 오른쪽 아래 12px "사진 : 촬영자 · CC BY-SA 4.0"(아래쪽 40% 어두운 그러데이션 위 흰 글자). 누르면 원본 주소를 새 탭으로. 사용 허가(CC BY·BY-SA)가 요구하는 표기다.
- 음식 예시 사진에는 "예시" 12px 표를 붙인다 — 그 가게의 실제 음식으로 오해하지 않게.
- 준비 탭 "참고 자료" 맨 아래에 이 도시 화면에 쓰인 사진 출처를 모두 적는다.

## 10. 직항이 없는 도시 · 고른 박 수의 일정이 없는 도시

### 10-1. 직항이 없는 도시 (예 : 김포 출발이면 33곳 중 25곳이 직항 없음)
| 화면 | 처리 |
|---|---|
| S1 지역 이름표 | 숫자 = 직항 도시 수. 0곳이면 알약 회색 + 지역 색 반쯤 빠짐(눌림은 그대로) |
| S2 지도·카드 | 흑백 표시, 카드 아래 "✈ 김포 직항 없음" 산호색 13px, 직항 있는 도시 뒤로 |
| S3 미리보기 | 항공 줄 대신 산호색 상자 : "김포에서는 직항이 없어요" / "직항 있는 공항 : 인천 · 김해 · 청주" / [인천 출발로 바꾸기] 버튼 44px. 대체 여행지 중 직항 있는 곳을 "직항으로 갈 수 있는 비슷한 곳" 으로 먼저 |
| S4 여행 화면 | 일정 탭 맨 위 한 줄 띠(닫기 가능) 같은 문구. 예산 항공 줄에 "직항 기준 값" 12px |

### 10-2. 고른 박 수의 일정이 없는 도시
- 지금 자료는 33곳 모두 2·3·4박이 있어 "아직 몰라요" 만 해당 → 그 도시 `recommended_nights[0]` 로 연다.
- 자료가 늘어 생기면(예 : 5박을 골랐는데 4박까지만 있음) : 같은 박 수가 없으면 **짧은 쪽 중 가장 긴 것**, 그것도 없으면 긴 쪽 중 가장 짧은 것. 미리보기와 여행 화면 위에 햇빛색 띠 "5박 6일 일정은 아직 없어요. 4박 5일로 보여 드려요". 지도 표시엔 "4박까지" 표.
- 주소가 없는 박 수로 들어오면(`#trip/kyoto/5`) 위 규칙으로 고친 주소로 바꿔 끼운다.

## 12. 바닐라 JS 한 파일로 만들 때 주의점

1. **주소 하나로 화면을 정한다.** `route = parse(location.hash)` → `{screen, region, city, nights, variant, day, tab, overlay}`. `nav(route, {replace})` 로만 주소를 바꾸고, `popstate` 에서 이전 route 와 비교해 바뀐 부분만 다시 그린다. 언어 메뉴 링크는 지금 주소(#)를 그대로 붙인다.
2. **화면 전체를 다시 그리지 않는다.** 지금은 핀 하나 눌러도 지도 SVG 를 통째로 다시 만든다(`innerHTML = jpMapSvg()`). 새 구조는 층을 나눈다 : 지도 무대(SVG 한 번만 만듦, 이후 class 와 viewBox 만 바꿈) / 도시 표시 HTML 층 / 시트 / 덮개.
3. **도시 표시 위치 계산** : 지도 단위 → 화면 px 은 `svg.getScreenCTM()` 로 바꾼다. 확대 애니메이션 중에는 표시를 숨기고 끝난 뒤 한 번만 계산한다(33개라 가볍지만 매 프레임 계산은 아이폰에서 끊긴다).
4. **시트 부품 두 가지를 섞지 않는다.** ① 늘 떠 있는 시트(지도 화면·여행 화면, 단계 3개, 모달 아님 → 지도도 같이 눌림) ② 모달 덮개(이미 틀에 있는 `openSheet/closeSheet`, 뒤로 가기로 닫힘). ①은 높이를 바꾸지 말고 `transform:translateY` 로 움직인다(화면 다시 배치가 안 일어나 부드럽다). 끌기는 손잡이·탭 줄에서만, 놓을 때 속도를 보고 가까운 단계로.
5. **아이폰 사파리** : 높이는 `100dvh`(없으면 `window.innerHeight` 를 CSS 변수로) 를 쓰고 `resize`·`visualViewport` 변화 때 단계 높이를 다시 잰다. 시트 속 스크롤은 `overscroll-behavior:contain`. 문서 자체는 스크롤하지 않으므로(`html,body{height:100%;overflow:hidden}`) 당겨서 새로고침 사고도 막힌다. 안전 영역(`env(safe-area-inset-*)`)을 위쪽 줄·시트 아래에 더한다. 검색창은 16px 이상(작으면 화면이 확대됨), 키보드는 누름 처리 안에서 바로 `focus()` 해야 뜬다.
6. **지도 손가락 처리** : 지도 무대에 `touch-action:none`, 포인터 이벤트로 "누름(8px 미만 움직임·300ms 미만)", "두 번 누름", "두 손가락 벌리기/오므리기(30% 넘게)" 만 구분한다. 연속 확대·끌기는 만들지 않는다.
7. **Leaflet 은 하나만** 만들어 탭·일차·도시를 바꿔도 재사용한다(지금은 일차 바꿀 때마다 지우고 새로 만든다). 표시 묶음(layerGroup)만 갈아 끼운다. 시트가 가리는 만큼 `paddingBottomRight` 를 준다. 지도 그림 서버 순서(지리원 → OSM → 약도)는 그대로.
8. **그림은 한 번만 넣고 여러 번 쓴다.** 도시 그림 33·음식 그림 23·지역 장면 9를 숨긴 `<svg>` 안 `<symbol id="ci-kyoto">` 로 두고 `<use href="#ci-kyoto">` 로 부른다. 그림 속 그러데이션·자르기 id 가 서로 겹치지 않게 조립 때 그림마다 앞에 키를 붙인다(예 : `kyoto-g1`). 지금처럼 카드마다 SVG 원문을 복사하면 DOM 이 커진다.
9. **사진은 늦게 푼다.** `photos.json` 을 `data:` 로 넣으면 파일이 커진다(대표 720×480 WebP 약 40KB × 33 + 명소 사진). `DATA` 안에 넣지 말고 별도 `<script type="application/json" id="PHOTOS">` 에 두고 화면에 보일 때만 꺼내 `img.decode()` 뒤에 보이게 한다. 목록에는 `content-visibility:auto`.
10. **6개 언어 길이** : 탭 4개(390px 에서 한 칸 약 86px)는 영어·스페인어에서 넘친다 → 글자 14px 까지 줄이고 그래도 넘치면 아이콘 + 짧은 말. 일차 알약 아래 이름은 360px 미만에서 숨긴다. 지역 이름표는 언어마다 폭을 재서(기존 `textW`) 겹침을 다시 확인한다. 번역이 없는 문장(한국어만)은 기존처럼 숨긴다(`kText`).
11. **기기 저장** : 기존 키(`origin`, `nights`, `picks`, `checks`)는 이름·모양을 바꾸지 않는다(이미 쓰던 사람의 체크 표시 유지). 새 키 `seen_start`, `tag`, `recent`. 모두 `try/catch`(사생활 보호 모드).
12. **읽어 주기·키보드** : 지역 칠한 곳은 `role="button"` + `aria-label="간사이, 직항 4곳"`, Enter 로 눌림. 늘 떠 있는 시트는 `role="region"`(모달 아님), 덮개만 `role="dialog"`. 덮개를 닫으면 누른 버튼으로 포커스를 돌린다(기존 코드 그대로).
13. **화면 점검(플레이라이트)** : 390×844, 320×568, 430×932, 안드로이드 412×915. 점검 장면 : 첫 방문 4탭 흐름 / 공유 링크로 들어와 뒤로 가기 3번(앱 밖으로 안 나가야) / 덮개 연 채 뒤로 가기 / 언어 바꾼 뒤 같은 화면 / 김포 출발(직항 없음 25곳) / 인터넷 끊김(약도) / 모든 탭 목표 44px 이상·글자 12px 이상 자동 측정 / 가로 스크롤 0.

## 14. 이 설계의 약점

1. **지리를 모르는 사람에게 '지역부터'는 벽이다.** 일본이 처음인 사람은 주고쿠·주부·도호쿠가 어디인지 모른다. 인기 도시 카드와 검색, 목록 보기로 피해 가게 했지만, 지도가 주인공이라는 전제 자체가 약간의 지리 감각을 요구한다. 지역 이름표에 대표 도시를 같이 쓰면 이름표가 커져 서로 겹친다.
2. **지도가 두 종류다.** 홈은 색 지도(그림), 여행 화면은 실제 지도(Leaflet). 미리보기 → 일정으로 넘어갈 때 지도 모양·색이 바뀌어 '같은 지도를 확대한다' 는 느낌이 끊긴다. 인터넷이 없으면 여행 화면 지도는 번호 약도라 '지도 중심' 이 가장 약해지는 곳이 하필 일정 화면이다.
3. **겹이 많다.** 지도 + 늘 떠 있는 시트(3단계) + 시트 안 탭 + 시트 안 상세 + 모달 덮개. 뒤로 가기 길이 복잡해지고, 아이폰 사파리에서 시트 끌기·시트 안 스크롤·주소창·키보드가 부딪히는 버그가 날 가능성이 이 설계에서 가장 높다. 점검 비용이 크다.
4. **문서가 스크롤하지 않아 사파리 주소창이 접히지 않는다.** 세로 약 80px 을 늘 잃는다. 아이폰 SE(568px)에서는 여행 화면 중간 단계에 장소 줄이 2~3개밖에 안 보인다.
5. **연속 확대가 없다.** 두 단계(일본 ↔ 지역)만 있어 손가락으로 더 크게 보려는 사람은 답답할 수 있다. 간사이는 도시 표시 간격을 지키느라 지역 모양이 잘려 '어디쯤' 맥락이 약해진다. 규슈·주부는 표시 간격이 57px 로 기준(64px)에 못 미쳐 이름표를 숨기는 경우가 생긴다.
6. **숨긴 정보를 놓칠 수 있다.** 영업시간·휴무·'확인 필요' 가 상세 안으로 들어간다. 달력 아이콘으로 휴무가 있다는 것만 알리지만, 요일까지 보려면 눌러야 한다. 여행 날짜를 받지 않으므로 "그날 휴무" 경고를 자동으로 줄 수 없다.
7. **그림이 단조롭다.** 음식 그림은 종류별 공용이라 라멘집 17곳이 같은 그림이다. 명소는 분류 아이콘뿐이라 '예쁜 실물 이미지' 요구에는 사진이 들어오기 전까지 못 미친다. 숙소는 사진 계획이 없다.
8. **사진을 파일 안에 넣으면 무겁다.** 지금 약 3.6MB 가 사진 넣으면 7~8MB 로 늘 수 있다. 첫 열림이 느려지고 메일 첨부 한도에 걸릴 수 있다.
9. **박 수를 바꾸는 곳이 세 군데**(첫 질문 · 미리보기 · 여행 화면 알약)라, 값은 하나여도 사용자는 어디서 바꿨는지 헷갈릴 수 있다.
10. **판매 연결이 없다.** 여행사·항공사에 팔 때 필요한 '예약하기·상담하기' 자리를 정하지 않았다. 지도 탐색 중심이라 그런 버튼을 어디에 둘지 따로 설계해야 한다.
11. **6개 언어에서 지도 이름표가 다시 겹칠 수 있다.** 영어 'Chugoku 3', 스페인어 탭 이름 등 길이가 달라 언어마다 자리를 다시 점검해야 한다.
12. **전체 지도에서 항로 곡선을 뺐다.** '인천에서 바로 간다' 는 이 앱의 핵심 메시지가 첫 화면에서 덜 보인다(고른 도시에만 한 줄).
