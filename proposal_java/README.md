# 메리츠 스마트 제안서 — 자바 판 안내

세일즈혁신TF · 2026-11-26 · 계산 버전 v9.14(파이썬 판과 같은 계산)

안녕하세요, 세일즈혁신TF입니다.
파이썬 서버를 두기 어려운 환경에서도 쓰실 수 있도록, 스마트 제안서 생성 프로그램을 **자바로 그대로 옮긴 판**입니다.
담보 목록(단위상품코드 · 담보코드 · 상품담보명 · 가입금액)을 JSON 으로 넘기면 스마트 제안서 PDF(13~17쪽)가 나옵니다.

- 파이썬 판과 **같은 입력에 같은 결과**가 나오도록 함수 하나하나를 1:1 로 옮겼고, 단계마다 파이썬 판 결과와 전부 대조했습니다(맨 아래 「검증」).
- 바깥 인터넷 · LLM · 외부 API 를 쓰지 않습니다. 필요한 것은 **자바 17 이상**과 **Edge · Chrome · Chromium 중 하나**뿐입니다.
- 바깥 부품은 Apache PDFBox(Apache License 2.0) 하나입니다(lib/ 4개 파일 · 3.7MB). 브라우저는 자바 기본 기능으로 직접 조종합니다.

---

## 1. 들어 있는 것

| 위치 | 무엇 |
|---|---|
| `smart-proposal.jar` · `lib/` | 실행 파일 |
| `data/` | 자료 — 특약 마스터 · 지급 규칙 · 금액표 · 분류표 · 지면 틀 · 글꼴. **파이썬 판의 파일을 그대로 복사한 것**입니다(자바 판에 따로 둔 자료는 없습니다) |
| `start.bat` · `start.sh` | 서버 켜기 |
| `examples/code_input_example.json` | 입력 예시(가짜 값) |
| `src/` | 소스 전체(pom.xml · 자바 소스 · 옮기기 규칙 `PORTING.md` · 정답지를 뽑는 스크립트 `golden/`) |
| `VERSION.txt` | 계산 버전 · 만든 날 |

## 2. 준비물

- **자바 17 이상**(JDK 또는 JRE). 확인 : `java -version` — 개발 · 검증은 자바 21 에서 했습니다.
- **브라우저** : Edge · Chrome · Chromium 중 하나(지면을 PDF 로 그리는 데 씁니다 · 화면은 뜨지 않습니다).
  - 윈도우는 기본 설치 경로의 Edge · Chrome 을 자동으로 찾습니다. 다른 곳에 있으면 환경변수 `GA_CHROMIUM=<실행 파일 경로>` 로 알려 주세요.
  - 리눅스 서버는 `chromium` · `google-chrome` 이 PATH 에 있거나 `GA_CHROMIUM` 으로 알려 주시면 됩니다.

## 3. 실행

### 한 건 만들기(명령줄)

```
java -jar smart-proposal.jar --json examples/code_input_example.json 결과.pdf
java -jar smart-proposal.jar --check examples/code_input_example.json      # PDF 없이 입력 점검 + 담보 인식 결과만
java -jar smart-proposal.jar --version
```

결과 PDF 옆에 계산 로그(`결과_log.txt` — 빈칸 · 0원이 된 이유)가 함께 남습니다. 종료코드는 0(정상) · 2(입력이 사양과 다름 · 만들지 않는 설계) · 1(그 밖의 오류)입니다.

### 서버로 띄우기

```
java -jar smart-proposal.jar serve                  # http://127.0.0.1:8080
java -jar smart-proposal.jar serve 0.0.0.0 8080     # 다른 PC 에서 접속하게
```

윈도우는 `start.bat`, 리눅스 · 맥은 `start.sh` 를 실행하셔도 됩니다.

| 주소 | 응답 |
|---|---|
| `GET /health` | `{"ok":true,"version":"…","engine":"java",…}` — 멈춘 뒤에는 503 |
| `POST /v1/ga2/json/pdf` | 스마트 제안서 PDF(`application/pdf`) |
| `POST /v1/ga2/json/all` | JSON — 쪽수 · 간병인 쪽 · 인식 담보 · 계산 로그 · `pdf_base64` |
| `POST /v1/ga2/json/check` | PDF 를 만들지 않고 입력 점검 + 담보 인식 결과만(빠름) |

요청 본문은 `Content-Type: application/json`(UTF-8 · 상한 2MB)이고, 사양은 파이썬 판과 같습니다.

```json
{
  "schema": 1,
  "design_no": "가계약번호",
  "product": "(무) 메리츠 통합간편건강보험(세만기형)2610(통합간편심사형) (해약환급금미지급형)",
  "premium": 123450,
  "insured": {"name": "홍길동", "sex": "M", "age": 45},
  "agent": {"org": "○○본부", "code": "00000", "name": "김메리", "mobile": "010-0000-0000", "tel": "02-0000-0000"},
  "riders": [
    {"no": 1, "unit_code": "X0000", "code": "000001", "name": "암진단비(유사암제외)(통합간편가입)", "amount": 30000000}
  ]
}
```

- `product` · `riders[].name` · `riders[].amount` 는 필수입니다. **담보명은 정보계 원문 그대로** 넘겨 주세요(엔진이 이름에서 조건을 읽습니다).
- 오류는 모두 `{"ok":false,"error":"…"}` 로 옵니다 — 400(사양과 다름 · JSON 아님 · 2MB 초과) · 422(만들지 않는 설계 · 담보를 하나도 못 찾음) · 500(생성 중 오류) · 503(대기 180초 초과 · 재시작 필요) · 504(1건이 `GA2_TIMEOUT` 초(기본 600)를 넘김).
- 응답 필드 · 오류 글자는 파이썬 판 `/v1/ga2/json/*` 과 같습니다(자세한 설명은 파이썬 판 안내 `IT_GA_V2.md` 5장).

```
curl -X POST -H "Content-Type: application/json" --data-binary @examples/code_input_example.json http://127.0.0.1:8080/v1/ga2/json/pdf -o 결과.pdf
```

### 환경변수(자바 속성 `-D이름=값` 으로도 됩니다)

| 이름 | 뜻 |
|---|---|
| `SP_HOME`(`-Dsp.home`) | 자료 폴더. 주지 않으면 jar 옆의 `data/` 를 씁니다 |
| `GA_CHROMIUM` | 브라우저 실행 파일 경로 |
| `GA_CODE_MAP` | 담보 식별표 `code_map.json` 경로(사내 자료 · 묶음에 없음). 없어도 됩니다 — 그때는 이름으로만 찾습니다 |
| `GA_MASK=1` | 피보험자 · 가계약번호 · 소속 · 컨설턴트 · 전화를 가린 견본 |
| `GA2_TIMEOUT` | 서버에서 1건 제한 시간(초 · 기본 600) |
| `SP_TMP` | 중간 파일 폴더(기본 `data/out/v2tmp` — 건마다 만들고 끝나면 지웁니다) |

## 4. 운영하실 때 알아 두실 것

- **한 번에 1건**씩 처리합니다(프로세스 하나 기준 · 1건 약 4초 · 첫 건은 브라우저를 띄우느라 7초쯤). 동시에 오면 차례로 처리하고 2건까지 받아 둡니다. 처리량을 늘리시려면 프로세스를 여러 개(포트마다 하나) 띄우고 앞에 부하분산을 두시면 됩니다. 프로세스마다 메모리는 1GB 쯤 잡아 주세요.
- `GET /health` 가 503 이면 프로세스를 다시 켜 주세요.
- 인증이 없고 CORS 는 모든 출처를 허용합니다. 사내망 안에서만 여시고, 인증 · 허용 출처는 앞단(게이트웨이)에서 맞춰 주시면 좋겠습니다.
- 지면을 그리는 브라우저(Edge · Chrome)가 켜질 때 제조사 주소(업데이트 확인 등)로 접속을 시도할 수 있습니다. 막혀 있어도 동작에는 지장이 없습니다(검증 환경도 막힌 상태였습니다). 프로그램 자체는 바깥으로 아무것도 보내지 않습니다.
- 서버는 결과를 저장하지 않습니다. 중간 파일은 건마다 지우고, 처리 중 꺼져서 남은 것은 서버를 켤 때 치웁니다.
- 자바 클래스는 전역 상태를 쓰기 때문에 **한 프로세스 안에서 여러 건을 동시에 계산하면 안 됩니다**(`Api` 가 작업 스레드 하나로 줄을 세웁니다). 다른 시스템에 클래스를 직접 넣어 쓰실 때도 `GaV2.build` 를 한 번에 하나씩만 불러 주세요.

## 5. 받으신 뒤 확인(인수 시험)

파이썬 없이 확인하실 수 있습니다. TF 가 드리는 「인수 시험 세트」 폴더(입력 JSON + 파이썬 판이 만든 정답 PDF · 요약)를 넣어 주세요.

```
java -jar smart-proposal.jar --selftest <인수 시험 세트 폴더>
```

입력마다 PDF 를 만들어 ① 쪽수 · 간병인 쪽 · 인식 담보 수 · 계산 로그 ② 쪽 크기 ③ **쪽별 글자와 위치**가 정답과 같은지 견주고, 「결과 : 전부 통과 — N건 · N쪽」 을 냅니다(다르면 무엇이 어디서 다른지 적고 종료코드 1). 만든 PDF 는 그 폴더의 `out/` 에 남습니다.

## 6. 파이썬 판과 다른 점(일부러)

- **입력은 담보코드 입력(JSON)만** 받습니다. 설계서 PDF 를 읽는 기능은 옮기지 않았습니다 — 전산 연결은 JSON 으로 하고, PDF 표 읽기를 다른 부품으로 다시 짜면 「같은 결과」 를 보장할 수 없기 때문입니다. PDF 주소(`/v1/ga2/pdf` 등)는 400 으로 안내합니다.
- 업로드 화면(`/`)은 없습니다(짧은 안내 글자만).
- 결과 PDF 크기가 조금 작습니다(약 2.4MB · 파이썬 판 3.5MB). 같은 그림을 한 벌만 담기 때문이고, 모양 · 글자는 같습니다.
- 틀린 JSON 일 때 `JSON 으로 읽지 못했습니다 : ` 뒤의 까닭 글자가 다릅니다(파이썬은 영문).
- `/health` 에 `engine` · `java` 항목이 더 있습니다.

## 7. 계산 · 약관이 바뀔 때

- 계산의 기준은 파이썬 판(`proposal_smart/`)입니다. 약관 개정 · 신담보는 TF 가 파이썬 판에 먼저 반영 · 검증하고, 같은 함수를 자바 판에 똑같이 고친 뒤 **정답지 대조를 전부 다시 통과시켜** 새 묶음을 보내 드립니다.
- 자료만 바뀐 경우(특약 마스터 · 규칙 · 금액표)는 `data/` 폴더만 바꾸면 됩니다(자바 코드는 그대로).
- 옮긴 규칙 · 단계별 대조 방법은 `src/PORTING.md` 에 있습니다.

### 아직 확인하지 못한 것(인수 시험 때 함께 봐 주시면 감사하겠습니다)

- **윈도우**에서의 실행(Edge · Chrome 경로 찾기 · 임시 폴더 지우기) — 개발 환경이 리눅스라 시험하지 못했습니다.
- **자바 17** 에서의 실행 — 17 용으로 컴파일했지만 실제 실행은 자바 21 에서만 했습니다.
- 브라우저 판이 크게 다르면(검증은 Chromium 153) 글자 자리가 아주 조금 달라질 수 있습니다. `--selftest` 가 알려 줍니다.
- 수술 카드 합계 ≠ 보장요약 같은 안전장치가 걸리는 길 · 대기 180초 초과(503) · 한 동작 120초 제한은 그런 상황을 만들지 못해 시험하지 못했습니다.
