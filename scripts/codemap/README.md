# 정보계 담보코드 ↔ 특약 마스터 매핑

회사 정보계의 「단위상품코드 · 담보코드 · 상품담보명」 표를 우리 특약 마스터(14개 상품, 약관 파싱)에 맞춘다.
IT개발파트는 정보계 담보코드로 특약을 가리킨다. 그래서 스마트 제안서 · 세일즈북 생성기 · 영업지원도구를 사내 전산으로 옮길 때 이 표가 다리 역할을 한다.

**정보계 엑셀과 결과 엑셀은 사내 자료다. 저장소에 넣지 않는다.** 이 폴더에는 스크립트만 둔다(스크립트 안에도 코드 번호를 적지 않는다).

## 돌리는 순서

작업폴더는 저장소 밖(세션 작업폴더)에 둔다.

```
cd scripts/codemap
python3 extract_rows.py <정보계 엑셀> <작업폴더>      # 엑셀 → rows.json(_x0036_ 같은 글자를 되돌림)
python3 toc.py <작업폴더>                               # 저장소 루트 약관 PDF 의 특약 목차 → terms_txt/toc.json(pdftotext 필요)
python3 run2.py <작업폴더>                              # 정보계 이름마다 우리 특약에 맞춤 → name_res.pkl
python3 build.py <작업폴더> <결과 엑셀>                 # 결과 엑셀(시트 8개)
```

결과 엑셀에는 집계 수식이 있다. 엑셀에서 열면 저절로 계산된다.

### 담보코드 기준 스마트 제안서 설계도(IT개발파트 전달용)

```
(cd ../../proposal_smart/ga_docs && python3 run_spec.py <GA 결과 json> <html폴더> <설계서.pdf ...>)   # 칸 정의 · 칸별 지급 줄 · 설계서 칸 값 — proposal_smart/ga_docs/README.md
python3 build_blueprint.py <작업폴더> <결과 엑셀> <GA 결과 json> <설계도 엑셀>   # 시트 10개
```

기존 GA 설계도(`dist/ga-blueprint-final.xlsx` · 담보명에서 출발)를 「단위상품코드 + 담보코드」에서 출발하도록 다시 짠 것이다. 계산 규칙 · 칸 사례 · 금액표는 같고, 담보를 찾는 열쇠만 바뀐다.
흐름 · 입력 데이터 사양 · 담보 식별표(짝마다 특약 마스터 ID — 단위상품코드의 추정 상품 안에서 같은 알맹이 · 같은 갱신형 여부 특약을 고른다) · 담보코드별 계산 사양(규칙 · 금액식 · 빈도 · 질병코드 판정 · 약관 KCD) · GA 칸 × 담보코드 · 계산 제외 · 단위상품코드 · 예외 처리 · 설계 예시 3건.
**설계도 엑셀에도 정보계 코드가 들어 있다 — 사내 자료, 저장소에 넣지 않는다.**

마스터 이름 띄어쓰기 점검(약관 줄바꿈 자리에 끼어든 띄어쓰기 · 「주요치 료비」 「연 간1회한」)은 따로 돌린다.

```
python3 spacing.py <작업폴더> <결과 엑셀>               # 고칠 이름 · 약관 표기 그대로 · 판단 보류
```

비교 · 계산은 띄어쓰기를 지우고 하므로 매핑과 지급 판정에는 영향이 없다. 화면과 설계도에 보이는 이름의 문제다. 고치는 것은 영업지원도구 `scripts/fix_name_spacing.py --write` · 보강 마스터는 추출기가 자동(규칙 `scripts/name_spacing.py` · proposal_smart/README v8.86).

## 맞추는 원칙

- 특약 알맹이가 같으면 같은 담보다.
- 고지 구분자 (맞춤간편가입) · (편한가입) 등, [기본계약], 앞의 「갱신형」, (N년갱신) 은 무시한다.
- [특별조건부] · [계약전환용] · (출생전) · 전환용 · 「추가」 는 정보계 코드가 따로 있다. 같은 우리 특약에 붙이되 「변형 표시」 칸에 적는다.
- 판정 단계는 다섯 가지다.
  - ① 정확 : 이름이 글자까지 같다.
  - ② 세부표기 : 괄호 · 순서 · 줄임 표기만 다르다.
  - ③ 특약단위 : 회사는 세부보장(종별 · 급별 · 암종별)마다 코드를 나누고, 우리는 특약 하나로 둔다.
  - ④ 유사 : 사람이 확인해야 한다(대개 체증형 · 10년후2배지급 같은 다른 판).
  - ⑤ 없음 : 우리 약관에 그 담보가 없다.
- 체증형은 같은 특약으로 본다. 스마트 제안서 · 보상시뮬레이터는 첫 보상을 예시로 보여 주기 때문이다(소유자 2026-11-06). 10년 뒤 2배 체증형은 프리미엄 건강보험 · 프리미엄 간편보험에만 있고, 프리미엄은 스마트 제안서에 넣지 않으므로 「분류 안 됨 · 대상 아님」으로 둔다.
- 「없음」은 약관 20개 목차와 대조한다. 우리 약관에 특약으로 있는데 마스터에 없으면 「마스터 누락 의심」으로 표시한다.
- 같은 알맹이는 「부모 특약 낱말 + 세부보장만의 낱말」로 묶는다. 예를 들어 「암진단및치료비Ⅱ[암진단및치료비Ⅱ[암진단비(유사암제외)]]」와 「암진단및치료비Ⅱ[암진단비(유사암제외)]」는 같은 묶음이다.

## 알아낸 것(2026-11-06 표 기준)

- **담보코드와 이름은 1:1 이 아니다.** 정보계는 담보 개념마다 코드를 주고 상품마다 다른 이름을 붙인다. 예를 들어 코드 하나가 케어프리에서는 「뇌졸중진단비」, 통합간편에서는 「뇌졸중진단비Ⅱ」다. 그래서 우리 특약은 「단위상품코드 + 담보코드」 짝으로 찾는다. 결과 엑셀의 「전체 행」 시트가 짝마다 맞춘 표다.
- 단위상품코드는 상품명이 아니라 「상품 × 고지유형 × 특약 묶음」 단위다. 어느 상품인지는 담보 구성과 고지 구분자로 추정했다(「단위상품코드 추정」 시트 · 추정 표시).
- 코드 앞 세 자리 계열(610 상해, 630~635 질병 · 암 · 뇌심 등)의 뜻은 회사 정의가 아니라 이름 분포로 본 추정이다.
- **정보계는 1-7종 수술비 세부보장을 부모 이름 없이 「수술비[질병3종]」으로도 쓴다.** 같은 코드에 「수술비(1-7종, 연간3회한)[질병3종](편한가입)」 이 함께 붙은 것으로 확인했고, 단위상품마다 질병 · 상해 1~7종 14개가 한 벌이다. 처음엔 「우리 약관에 없음」으로 빠졌던 91개 코드를 1-7종 수술비에 붙였다(`match.SUB17` · 2026-11-06).
- **엔진 보완 거리** : 정보계 이름에만 붙는 [특별조건부] · [계약전환용] · (출생전) 표시가 있으면 지금 엔진은 통합치료비 약관 지급금액표를 못 찾아 계산 제외가 된다(189짝 · 이름 49개). 설계도는 이 표시를 떼고 읽는 것을 기준으로 적었다 — 전산 이관 때 엔진에서 떼도록 같이 고친다.
